My Git workflow

The routine you actually use — command line, Codex, or both. How do you inspect changes, choose a message, push, and verify the remote? If you use Codex because Git is new, ask it to show the proposed files and message before it acts. See the commit protocol in AGENTS.md.

  1. git status and git diff to see what actually changed.
  2. Stage named files — not git add ., so I notice anything unintended.
  3. Message in the form area: what and why, e.g. note: RT-01 first run, display lagged ~4 presses behind.
  4. Push, then open the repo in a browser and confirm the commit is really there.
  5. Copy the full commit ID for Canvas.

Evidence notes get their own commit, same day, so the timestamp means something. I do not batch them with code changes.

Codex use: I ask it to explain a diff before I commit. It has not committed on my behalf. If that changes, I record it here and in the AI-use table.

Technical debt is not a personal failure. It is the accumulated cost of moving quickly without yet making every part easy to understand and change. This manual is how you make that cost visible, decide what to address next, and build your ability to work with technical systems thoughtfully.
